# Техническое задание: Интеграция мобильной анкеты гостя с AmoCRM

Техническое задание на разработку и внедрение серверной интеграции мобильной анкеты гостя сети парков **Hello Park** с корпоративной CRM-системой **AmoCRM** (REST API v4).

---

## 1. Общие сведения и бизнес-цель

* **Модуль:** Мобильная веб-анкета гостя (`/guest-registration`) и Бэкенд интеграции.
* **Репозиторий GitHub:** [https://github.com/DimaHello/rfid-panel](https://github.com/DimaHello/rfid-panel)
* **Целевой аккаунт CRM:** `helloprk.amocrm.ru`
* **Бизнес-цели:**
  1. **Автоматический сбор клиентской базы:** Каждый зарегистрировавшийся в анкете родитель сразу попадает в базу AmoCRM в виде Контакта и Сделки.
  2. **Дедупликация:** При повторных визитах система находит существующий контакт по верифицированному номеру телефона и привязывает новую сделку к нему, сохраняя сквозную историю клиента.
  3. **Сохранение состава семьи и маркетинговых данных:** Полная информация о детях (имена, даты рождения, возраст), городе проживания и источнике привлечения фиксируется в ленте сделки.
  4. **Автономность и бесперебойность (Offline First / Graceful Degradation):** Процесс регистрации гостя на кассе не должен зависеть от стабильности внешних API. Если AmoCRM недоступна, клиент всё равно получает свой QR-код без задержки, а данные синхронизируются в фоновом режиме.

---

## 2. Архитектура потока данных (Data Flow)

```
[Смартфон гостя: Веб-анкета]
             │
             │ 1. Шаг 1: Верификация телефона по СМС
             │ 2. Шаг 2: Ввод ФИО и добавление детей
             │ 3. Шаг 3: Источник и город
             │ 4. Нажатие «Зарегистрироваться»
             ▼
[Клиентский скрипт: buildQR()]
             │
             ├──► Параллельно: Мгновенный рендер QR-кода на экране (гость готов идти на кассу)
             │
             └──► HTTP POST /api/register-guest (JSON)
                         │
                         ▼
             [Сервер приложения (Node.js / Go / Python)]
                         │
                         ├─► 1. Поиск контакта по телефону: GET /api/v4/contacts?query=+7...
                         │      (если найден — берем existing.id, если нет — POST /api/v4/contacts)
                         │
                         ├─► 2. Создание сделки в воронке: POST /api/v4/leads
                         │      (pipeline_id и status_id из конфигурации)
                         │
                         └─► 3. Добавление примечания с составом семьи: POST /api/v4/leads/{id}/notes
```

> **Важно:** Прямое обращение из браузера клиента к AmoCRM API запрещено из соображений информационной безопасности (утечка долгосрочного Bearer-токена в открытый трафик) и ограничений CORS.

## 3. Спецификация внутреннего API бэкенда

### Эндпоинт: `POST /api/register-guest`

#### Формат входящего запроса (Request Body JSON):
```json
{
  "v": 1,
  "fio": "Ильина Марина Владимировна",
  "phone": "+79265554433",
  "children": [
    {
      "name": "Даниил",
      "dob": "2017-08-20"
    }
  ],
  "city": "Москва",
  "source": "увидели в ТЦ",
  "sourceOther": null,
  "ts": 1784034500000
}
```

#### Поля запроса:
| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `fio` | string | Да | ФИО родителя |
| `phone` | string | Да | Номер телефона (формат E.164: `+7XXXXXXXXXX`) |
| `children` | array | Да | Массив объектов детей: `{ name: string, dob: string | null }` |
| `city` | string | Да | Выбранный город гостя |
| `source` | string | Да | Выбранный источник привлечения |
| `sourceOther` | string | Нет | Уточнение, если выбран источник «другое» |
| `ts` | number | Нет | Unix timestamp момента генерации анкеты |

#### Успешный ответ (HTTP 200 OK):
```json
{
  "success": true,
  "lead_id": 33927595,
  "contact_id": 37519841,
  "pipeline_id": 6548514,
  "status_id": 55736566
}
```

#### Ответ при ошибке (HTTP 500 / 400):
```json
{
  "success": false,
  "error": "AmoCRM POST /leads failed (401)",
  "details": null
}
```

## 4. Логика взаимодействия с AmoCRM API v4

Базовый URL: `https://<AMO_SUBDOMAIN>.amocrm.ru/api/v4`  
Авторизация: Заголовок `Authorization: Bearer <AMO_LONG_TOKEN>`

### Шаг 1. Дедупликация и обновление Контакта
Перед созданием сделки ищем контакт по номеру телефона:
```http
GET /api/v4/contacts?query=%2B79164443322
```

Формируем массив `custom_fields_values` для контакта, раскладывая детей и парк по системным полям:
* **Телефон (`PHONE`):** `+79164443322`
* **Парк (ID: `1361045`):** выпадающий список (enum):
  - `Мега`: ID `854845`
  - `Ривьера`: ID `854843`
  - `Воронеж`: ID `945949`
  - `Селигерская`: ID `943717`
  - `Сочи`: ID `870635`
  - `Владикавказ`: ID `915159`
  - `Сахалин`: ID `917537`
  - `Каспийск`: ID `942973`
  - `Авиапарк`: ID `854847`
* **Ребенок 1:**
  - `Имя 1` (ID: `1351959`): `София`
  - `День рождения 1` (ID: `1351961`, тип `birthday`): Unix timestamp даты рождения в секундах
  - `Флаг реб1` (ID: `1435221`): `"2025"` (прошлый год, чтобы триггер обзвона сработал в текущем 2026 году)
* **Ребенок 2 (если указан):**
  - `Имя 2` (ID: `1351967`)
  - `День рождения 2` (ID: `1351969`, тип `date_time`)
  - `Флаг реб2` (ID: `1435223`): `"2025"`
* **Ребенок 3 и 4 (если указаны):** аналогично поля `Имя 3` (`1351977`) / `Имя 4` (`1433331`), `День рождения 3` (`1351979`) / `День рождения 4` (`1433333`), `Флаг реб3` (`1435225`) / `Флаг реб4` (`1435227`).

Если контакт найден — обновляем его (`PATCH /api/v4/contacts/{id}`), чтобы актуализировать данные детей.  
Если контакт не найден — создаем новый (`POST /api/v4/contacts`).

### Шаг 2. Создание сделки с привязкой к воронке и тегами
* **Название сделки:** Формируется по правилу `{Имя_первого_ребенка} {ДД.ММ.ГГГГ}` (например, `София 25.11.2019`) — в точности так, как в существующих сделках обзвона, либо `Анкета гостя: {ФИО_Родителя}` (если ребенок не указан).
* **Теги:** Добавляются тег парка (например, `Мега`) и тег `анкета_гостя`.
* **Привязка:** Контакт привязывается через `_embedded.contacts`.

```http
POST /api/v4/leads
Content-Type: application/json

[
  {
    "name": "София 25.11.2019",
    "pipeline_id": 6548514,
    "status_id": 55736566,
    "_embedded": {
      "contacts": [{ "id": 37522357 }],
      "tags": [
        { "name": "Мега" },
        { "name": "анкета_гостя" }
      ]
    }
  }
]
```
В ответе возвращается массив созданных сделок. Получаем `lead_id = created._embedded.leads[0].id`.

### Шаг 3. Добавление Примечания в таймлайн карточки
Для удобства администраторов и менеджеров парка в ленту сделки добавляется отформатированное примечание:
```http
POST /api/v4/leads/33927595/notes
Content-Type: application/json

[
  {
    "note_type": "common",
    "params": {
      "text": "📝 Новая регистрация гостя (Анкета)\n━━━━━━━━━━━━━━━━━━━━\nРодитель: Ильина Марина Владимировна\nТелефон: +79265554433\nГород: Москва\nОткуда узнали: увидели в ТЦ\n\nДети (1):\n  1. Даниил (2017-08-20, ~9 лет)\n━━━━━━━━━━━━━━━━━━━━\nДата и время: 16.09.2026, 11:40:51"
    }
  }
]
```

#### Правило расчета возраста ребенка:
Возраст высчитывается автоматически на основе даты визита и даты рождения `dob` (полных лет с правильным русским склонением: `год`, `года`, `лет`).

## 6. Отказоустойчивость и безопасность

1. **Изоляция сбоев (Circuit Breaker / Non-blocking):**
   - Фронтенд выполняет запрос к `/api/register-guest` асинхронно в фоне.
   - Ошибка сети или недоступность сервера CRM **ни при каких обстоятельствах** не должна блокировать рендеринг QR-кода гостя на экране.
2. **Буферизация (для продакшн-сервера):**
   - В боевой инфраструктуре рекомендуется входящие JSON-анкеты сначала складывать в локальную очередь или таблицу БД (PostgreSQL / Redis / SQLite).
   - Воркер последовательно вычитывает заявки и отправляет в AmoCRM API с повторными попытками (retries) при HTTP 429 (Rate Limit) или HTTP 5xx.
3. **Лимиты запросов:**
   - AmoCRM API v4 имеет стандартный лимит: не более 7 запросов в секунду на аккаунт. Рекомендуется использовать задержку или троттлинг при пакетной отправке.
